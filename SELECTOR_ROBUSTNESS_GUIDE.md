# Making Skill Recordings More Robust
## Guide to Stable Selector Strategies

**Last Updated**: 2025-12-10

---

## The Problem: Brittle vs Stable Selectors

### Current State (Vancouver→LAX Recording)

The recorded skill has **mixed selector quality**:

```typescript
// ✅ STABLE - Works across different searches
"[aria-label=\"Where from? \"]"
"[aria-label=\"Where to? \"]"

// ❌ BRITTLE - Breaks when search changes
"//*[@id=\"c322\"]/div[2]/div[1]/div[1]"  // Vancouver dropdown result
"//*[@id=\"c489\"]/div[2]/div[1]/div[1]"  // LAX dropdown result
```

**What happens**:
- User records: Types "vancouver" → Clicks result with `id="c322"`
- User executes: Types "Toronto" → Google generates `id="d521"` (different!)
- **Result**: Element not found, Strategy 1 fails 100% of the time

---

## Selector Stability Hierarchy

### Tier 1: Most Stable (Always Use)

#### 1. ARIA Labels
```html
<input aria-label="Where from?">
→ Selector: [aria-label="Where from?"]
```

**Why Stable**:
- Accessibility requirement, rarely changes
- Semantic meaning (developers preserve these)
- Google Flights has used same labels for years

**Real Example from Recording**:
```typescript
{
  type: 'click',
  selector: '[aria-label="Where from? "]',  // ✅ Perfect!
  description: 'Click Where from?'
}
```

#### 2. Semantic HTML + Stable Attributes
```html
<button data-testid="search-flights">Search</button>
→ Selector: button[data-testid="search-flights"]
```

**Why Stable**:
- `data-testid`, `data-test`, `data-cy` are test hooks
- Teams don't change them without updating tests

#### 3. Role + Name Combination
```html
<div role="combobox" aria-label="Destination">
→ Selector: [role="combobox"][aria-label="Destination"]
```

**Why Stable**:
- Accessibility roles are semantic
- Combined selectors more specific

---

### Tier 2: Moderately Stable (Use with Caution)

#### 4. Meaningful CSS Classes
```html
<div class="flight-search-origin-input">
→ Selector: .flight-search-origin-input
```

**Why Risky**:
- ✅ Descriptive classes usually preserved
- ❌ Utility classes change frequently (e.g., Tailwind)
- ❌ Auto-generated classes break (e.g., `css-17dmc3a`)

**How to Identify Stable Classes**:
```
✅ GOOD: flight-card, search-button, price-display
❌ BAD: _1a2b3c, MuiButton-root, css-abc123
```

#### 5. Text Content Matching
```html
<button>Search Flights</button>
→ Selector: button:has-text("Search Flights")
```

**Why Risky**:
- ✅ Works if button text doesn't change
- ❌ Breaks with A/B tests ("Search Flights" vs "Find Flights")
- ❌ Internationalization changes text

---

### Tier 3: Unstable (Avoid)

#### 6. Auto-Generated IDs ❌
```html
<div id="c322">Vancouver</div>
→ Selector: //*[@id="c322"]
```

**Why Unstable**:
- Google generates IDs dynamically based on search
- Framework-generated IDs (React: `react-1`, `react-2`)
- Session-based IDs

**The Vancouver→Toronto Problem**:
```
Type "vancouver" → Google generates: <div id="c322">
Type "Toronto"   → Google generates: <div id="d815">  // Different!
```

#### 7. Position-Based XPaths ❌
```html
/html/body/div[2]/div[3]/ul/li[1]
```

**Why Unstable**:
- Adding a banner ad shifts everything: `div[2]` → `div[3]`
- Conditional elements (A/B tests) change positions
- Loading states add/remove elements

## Solution 1: Intelligent Selector Fallback System

### Implementation in `lib/capture/action-recorder.ts`

When recording a click, capture MULTIPLE selectors in priority order:

```typescript
async function recordClick(element: Element) {
  const selectors = {
    // Tier 1: Most stable
    ariaLabel: element.getAttribute('aria-label')
      ? `[aria-label="${element.getAttribute('aria-label')}"]`
      : null,

    dataTestId: element.getAttribute('data-testid')
      ? `[data-testid="${element.getAttribute('data-testid')}"]`
      : null,

    role: element.getAttribute('role')
      ? `[role="${element.getAttribute('role')}"]`
      : null,

    // Tier 2: Moderately stable
    semanticTag: getSemanticSelector(element),  // e.g., "button.submit-btn"

    // Tier 3: Fallback (least stable)
    xpath: getXPath(element),
  };

  // Store ALL selectors
  const action: RecordedAction = {
    type: 'click',
    primarySelector: selectors.ariaLabel || selectors.dataTestId || selectors.xpath,
    fallbackSelectors: Object.values(selectors).filter(Boolean),
    description: `Click ${element.textContent}`,
    timestamp: Date.now()
  };

  return action;
}

function getSemanticSelector(element: Element): string | null {
  const tag = element.tagName.toLowerCase();
  const classes = Array.from(element.classList)
    .filter(cls => !isAutoGenerated(cls))  // Filter out Tailwind, CSS modules
    .join('.');

  return classes ? `${tag}.${classes}` : null;
}

function isAutoGenerated(className: string): boolean {
  // Detect auto-generated class patterns
  return /^(_|css-|MuiButton-|tw-)/.test(className) ||
         /^[a-z]{1,2}\d+$/.test(className);  // e.g., "a1", "zz99"
}
```

### Playback with Fallback in `workflows/steps/execute-skill-step.ts`

```typescript
async function executeAction(action: RecordedAction, page: Page) {
  const selectors = [
    action.primarySelector,
    ...(action.fallbackSelectors || [])
  ];

  let element = null;
  let usedSelector = null;

  for (const selector of selectors) {
    try {
      element = await page.locator(selector).first();
      if (await element.isVisible({ timeout: 2000 })) {
        usedSelector = selector;
        break;
      }
    } catch (e) {
      continue;  // Try next selector
    }
  }

  if (!element) {
    throw new Error(`All selectors failed: ${selectors.join(', ')}`);
  }

  console.log(`[Selector Fallback] Used: ${usedSelector}`);
  await element.click();
}
```

**Expected Outcome**:
- If `aria-label` selector fails, tries `data-testid`
- If both fail, falls back to XPath
- Logs which selector worked for debugging

**Success Rate Improvement**: 40-60% (from current ~0%)

## Solution 2: Dropdown Result Smart Matching

### The Dropdown Problem

When user clicks "Vancouver, British Columbia, Canada" in autocomplete:

```html
<!-- What gets recorded -->
<div id="c322">Vancouver, British Columbia, Canada</div>
```

Current selector: `//*[@id="c322"]` ❌ Breaks

**Better Approach**: Match by **text content** instead of ID

### Implementation

```typescript
async function selectDropdownResult(value: string, page: Page) {
  // Type the value first
  await page.fill('[aria-label="Where from? "]', value);

  // Wait for dropdown to appear
  await page.waitForSelector('[role="listbox"]', { timeout: 3000 });

  // Find result by text content (fuzzy match)
  const options = await page.locator('[role="option"]').all();

  for (const option of options) {
    const text = await option.textContent();
    if (text && fuzzyMatch(text, value)) {
      await option.click();
      return;
    }
  }

  // Fallback: Press Enter to select first result
  await page.keyboard.press('Enter');
}

function fuzzyMatch(optionText: string, searchValue: string): boolean {
  // Normalize and compare
  const normalized = optionText.toLowerCase().replace(/[^a-z0-9]/g, '');
  const search = searchValue.toLowerCase().replace(/[^a-z0-9]/g, '');

  return normalized.includes(search) || search.includes(normalized);
}
```

**For Variable Substitution**:

```typescript
// Recording: User typed "vancouver", clicked result with id="c322"
// Store: { originalValue: "vancouver", selector: "//*[@id='c322']" }

// Execution: Variable is "Toronto"
// DO NOT use selector! Instead:
await selectDropdownResult("Toronto", page);  // Uses text matching
```

**Expected Outcome**:
- Works for ANY city, not just Vancouver
- Resilient to Google changing dropdown IDs
- No reliance on brittle selectors

**Success Rate Improvement**: 80-90% for autocomplete interactions

## Solution 3: Action Type-Specific Recording

Different interaction types need different selector strategies:

### Form Inputs (High Stability Needed)

```typescript
{
  type: 'fill',
  selector: '[aria-label="Where from? "]',  // ✅ Use aria-label
  value: '%origin%',
  strategy: 'stable',  // Mark as requiring stable selector
}
```

### Dropdown Selections (Content-Based)

```typescript
{
  type: 'select_dropdown',
  selector: '[role="listbox"]',  // Parent container (stable)
  value: '%origin%',
  matchStrategy: 'text_content',  // Use text, not element ID
  description: 'Select origin from dropdown'
}
```

### Button Clicks (Semantic Priority)

```typescript
{
  type: 'click',
  selectors: [
    'button[aria-label="Search"]',           // Tier 1: ARIA
    'button:has-text("Search")',             // Tier 2: Text
    'button.search-flights-button',          // Tier 3: Class
    '//*[@id="search-btn"]'                  // Tier 4: Fallback
  ],
  description: 'Click search button'
}
```

## Solution 5: Recorder Best Practices Guide

### For Users Recording Skills

**DO**:
- ✅ Type full city names, then press **Enter** (don't click dropdown)
- ✅ Use buttons with clear labels ("Search", "Done")
- ✅ Slow down between actions (2-3 seconds)
- ✅ Click center of elements (not edges)

**DON'T**:
- ❌ Click autocomplete suggestions if you can avoid it
- ❌ Record during slow page loads (wait for stability)
- ❌ Use browser back button (use site navigation)

### Recording Checklist (Show in UI)

```
Before you start recording:
☐ Page has fully loaded (no spinners)
☐ You know the exact steps you'll take
☐ You'll use keyboard (Enter/Tab) for dropdowns when possible

After recording:
☐ Review the quality report
☐ Fix any "high severity" selector warnings
☐ Test with different variables
```
